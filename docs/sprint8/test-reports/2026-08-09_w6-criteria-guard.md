## 四、🔴 验红：怎么做的、记录在哪、怎么防止再次蒸发

### 4.1 判据与做法

判据（主控给定）：**把 `plan_checks.py` 里整块 W6 判定删掉或改成恒不报，用例必须变红。**

做法：把 `core/plan_checks.py` 的源码**在内存里** AST 改写成残废版本
（`ast.parse` → 摘掉 `check_plan` 体内源码段含 `"W6"` 的顶层语句（跳过 docstring）→
`compile` → `exec` 到独立命名空间），再用**同一批 case 表**跑。三种残废件：

| 模式 | 改法 | 该翻面的那批断言 |
|---|---|---|
| `drop` | 整块 W6 判定**删掉** | 11 条"应报 W6"的 case |
| `always` | W6 改成**无条件上报** | 16 条"不该报 W6"的 case |
| `ordering` | `if fact_terms:` → `if True:`（"候选集空则早退"失效） | 12 条候选集为空的 case |

⚠ **为什么不在磁盘上真删**：①本代理的边界是**不碰 `core/` 任何生产代码**（权限层也拦下了写
`core/plan_checks.py` 的尝试）；②更实质的理由是 `docs/MEMORY.md` §6 那条纪律——
**验红本身不该在红的那一次污染工作区**（`/tmp/evil.py` 那次就是"红态真写了文件、还原代码后
测试仍红、白排查一轮"）。内存突变**逻辑等价、零磁盘写入**，且每轮回归都会重做一遍。

### 4.3 怎么防止再次蒸发（这是本次的主要交付，不是附带品）

上一轮的教训是「验红做过、脚本删了、保护力归零」。本次把验红做成**代码而非动作**，四道机制：

1. **验红是常驻用例，不是一次性脚本。** `test_red_state_drop_w6_block` /
   `test_red_state_always_report_w6` / `test_red_state_early_return_ordering` 三组
   共 39 条，**每次 `pytest` 都跑**。它们不是"跑过一次的证据"，是"每次都重新取证的仪器"。
2. **真实断言与验红断言共用同一张 case 表。** 正向 / 负向断言 parametrize 的是
   `_W6_EXPECTED` / `_W6_ABSENT` 两个模块级元组，突变断言 parametrize 的是**同一对元组**。
   ⇒ **往表里加一条 case，它自动同时获得"正向绿"与"红态会红"两重检查**；
   想加一条没牙的用例，在结构上就做不到。
3. **突变器活性金丝雀**（`test_mutation_actually_bites`）。若 W6 日后被重构到别处、
   突变器改写 0 条语句，它会拿着一个"和原件一模一样的突变体"跑出绿灯 —— 验红自己变假绿
   （S7-06「守门扫描面指错、扫 0 条却 passed」同型）。金丝雀断言：①至少改写 1 条语句；
   ②突变体在整张 case 表上**行为确实与原件不同**。两条任一不成立即报红。
4. **副作用自证 + case 表完整性自证**。`test_mutation_harness_is_side_effect_free` 每轮
   核一遍 `core/plan_checks.py` 未被改动；`test_case_tables_are_non_empty_and_disjoint`
   拦住"表被清空 / ID 重名 ⇒ 跑 0 条 case 然后 passed"这种假绿。

⇒ 一句话：**下次再有人删掉 W6 判定，红的不只是"某几条用例"，还有"证明那几条用例有牙"的那组用例。**

## 五、失败排查

**无失败。** 过程中自己写红过一次，记录如下（属测试代码 bug，已自修）：

- **用例**：`test_mutation_actually_bites[ordering]`
- **失败类型**：**测试代码 bug**（不是生产代码问题）
- **报错**：`AssertionError: 突变体与原件行为一致 ⇒ 突变没生效`
- **排查与结论**：金丝雀原先用**手挑的单条探针**（候选集非空 + 空话标准）判断"突变是否生效"。
  但 `ordering` 突变只在**候选集为空**时才与原件分道，该探针恰好选在两者一致的区域 ⇒ 误判成
  "突变没生效"。我最初还给它打了个 `or mode == "always"` 的补丁 —— 那是在**给错误的判据打补丁**，
  等于把金丝雀调哑。
- **处置**：**自行修复**，把探针从"手挑一条"改为"**扫整张 case 表，只要有任意一条分道即算生效**"。
  ⇒ 判据不再依赖"我挑得准不准"，且新增 case 会自动扩大金丝雀的探测面。
