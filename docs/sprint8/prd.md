## 0. 立项依据

### 0.1 第一层：一条从头断到尾的输出契约链

起点是 Maria 2026-08-03 真跑复盘的一句话：「我觉得有点框的太死了吧？也不一定所有论文都要输出 metrics 吧万一是定性的论文呢」。

| 环节 | 应该做什么 | 实际做了什么 | 源码依据 |
|---|---|---|---|
| 计划 | 声明每步该产出什么 | `expected_output` 一栏**全仓零判定消费点** | `planning.py:182`/`:250`；`ui/pages/plan_review.py:360` 唯一消费点是展示 |
| 编码 | 按声明产出结果文件 | **从没有人告诉过它 `summary.json` 或 `outputs/` 的存在** | `coding.py` 全文两者均零命中 |
| 执行 | 去读结果文件 | 在等一个没人被要求生产的文件；且**一个读文件的工具都没绑** | `execution.py:1733`；工具列 `:1581-1584` 只有三个 |
| 报告 | 呈现结果 | 靠一条即将失效的扁平字段渲染 | `reporting.py:963`、`ui/pages/result_report.py:178` |

**唯一一次告知发生在失败之后**：编码环节能听到 `summary.json` 的唯一通道，是零指标改判时回传的修复提示（`execution.py:2259-2263`）——**必须先失败一轮才可能知道要产出什么**。

### 0.2 第二层：结论档位定义本身的三个病

- 🔴 **病①：全局文档承诺的「与论文报告一致」，代码从来没实现过。** 全局定义是「指标在可接受偏差内一致」（`product-design-specification.md:402`），唯一实现 `_verify_trend`（`reporting.py:179-198`）**只做组间比大小**。⇒ **「跑出来的数跟论文对上了」评不上最高档。**
- 🔴 **病②：全有全无。** 门槛是 `all(check == "符合")`（`reporting.py:317`）⇒ **三个实验对上两个，与一条都没对上，评价完全相同。**
- 🔴 **病③：标准照着「有多组对照实验的论文」设计。** 无对照组的论文**结构性永远拿不到最高档**。

### 0.3 第三层（本版）：根源是「一套判据套所有论文」

Maria 审读架构文档时连问三层——「让执行环节自己判断归三类不难吧」→「前序节点有哪些产出到了这个节点」→ **「有论文分析和规划难道不能分析出来什么样算复现成功？」**

⇒ **此前反复撞的全部问题（定性论文判不了、无对照组的定量论文拿不到高档、指标必须有数值、档名不副实），根源都是「一套判据套所有论文」。** UMAP 与一篇纯理论论文的「成功」本就不是一回事。**本版是根治，前几轮是逐个补洞。**

### 0.4 Maria 拍板（四批，原样引用，不得更改）

**第一批·六条决策**：①「复现成功」不再硬性要求数值指标；②走文件路线；③**废掉 `<METRICS>` 标签通道**（是废掉不是收窄）；④不做硬解析，结构由编码环节自己定；⑤给执行环节读文件权限，判定交给 agent；⑥agent 判成功必须交可核验物证。

**第二批·档位重设计**（原话：「**我的诉求很简单就是让 execution 看产物自动判断是哪一档**」）：判定落点从报告环节挪到执行环节；三档变四档；判档同样要交物证，不新增第二套机制。

**第三批·四条裁定**：①第四态作废，逐条结论恢复三态；②造假审计改成给 agent 的证据输入，不再自动降档；③客观事实封顶保留；④审计盲区本次只登记不治。

**第四批·成功标准归属**（原话：「**有论文分析和规划难道不能分析出来什么样算复现成功？**」）：
- **成功标准由「系统硬编码一套、所有论文共用」改为「论文分析 + 规划针对本篇论文推导出来，写进计划」**，执行环节照这份**本篇专属**标准判档位。
- **四档保留作为统一表达框架**（档位名不变，保证报告可横向比较、界面不必做成完全动态），**变的是每档的具体判据**。
- **责任链闭合**：计划是人在回路审核过的 ⇒「这篇论文什么样算复现成功」是**用户批准过的**，与决策 1「计划要数值才要数值」同一逻辑，只是推到底。

## 2. 目标与非目标

### 目标

1. 🔴 **判定标准照着「这篇论文的复现成功意味着什么」设计**——本版总纲。前几轮是"照着复现成功意味着什么"（比"照着某类论文长什么样"进了一步），本版再进一步到**本篇专属**。
2. **一篇纯定性论文，代码跑通、图画出来，能判复现成功。**
3. **部分复现有名分**：三个实验对上两个，不再与一条没对上同等评价。
4. **「实验算出了什么」不再靠猜**：计划声明产出与成功标准 → 编码产出 → 执行照约取并判档 → 报告呈现。
5. **判断权交给执行环节，代码退居验钞**，并守住三条客观封顶。
6. 🔴 **成功标准是用户批准过的**：它写在计划里、在审核页显眼可见可改。

### 非目标（本次明确不做）

1. **不做看图判断**（不接多模态，`core/` 下无任何视觉链路）。
2. **不做通用多维指标容器**（反过度工程，MEMORY §4.1）。⚠ **v4.0 澄清**：本条**不与 S8-06 新方案冲突，反而同向**——新方案**不建任何容器**，而是让执行环节直接给出可呈现的结果块，代码只提供通用渲染原语。它比方案 A**更少**抽象（方案 A 还要维护"组名拼接规则 + 撞名处置"）。本条禁的是"在状态里造一个能装 N 维的复杂容器类型"，不是禁"不预设形状"。
3. **不在命令层新增伪造拦截规则**（§4.9.4，该路已被既有架构定过价）。
4. **不治造假审计的盲区**（裁定 4）。
5. **不在编码提示词里教「怎么写才不被审计命中」**。
6. 🔴 **不让计划改动四档的语义边界**（§4.5.2 两层分离）——计划只填达标线。
7. 🔴 **护栏 3 不做成阻断门**（§4.11.3）——沿用「只产警示、不阻断审批」的既有契约。
8. **不新增中断种类 / 决策按钮 / 流程分支**；**不改编排图**；**不做人工确认预期结论的交互入口**。
9. **不修步骤对账归属机制**；**不做复现成功率 KPI**；**不做图片内嵌渲染**。
10. 🔴 **v4.0 新增：不把结果块的展示上限做成 `config.py` 可配置项**——它们是渲染确定性的一部分，配置化会让同一份状态渲染出不同报告（反过度工程）。落 `reporting.py` 模块级常量即可，沿 `_NEST_MAX_DEPTH` / `_LIST_INLINE_MAX`（`reporting.py:435`/`:437`）既有先例。
11. 🔴 **v4.0 新增：不在渲染层做"结构推导/ 列名猜测"启发式**——展示元信息一律由执行环节随结果一起给出。渲染层去猜，等于把"预设格子"换个地方重建。

## 4. 需求详述

### 4.1 S8-01 计划声明「该产出什么」+「什么算成功」（**本版扩围**）

#### 4.1.1 原有射程（产出声明）

`execution_steps` 是 `{step_name, command, expected_output}` 三元组（`planning.py:182`/`:250`），`expected_output` **全仓零判定消费点**（唯一消费点 `ui/pages/plan_review.py:360` 是展示表格）。与 S7-13 砍掉的 `metrics[].source`、R-S4-01 守着的 `steps_attempted` 同型——**写了没人看的字段**。

1. **`deliverables` 语义扩为「本次复现应当落地的产物」**（复裁 2）。
2. `expected_output` 要求写清产出文件的相对路径，**作为给编码环节看的说明**。
3. 这份清单**不是档位判据**，而是四档中「产物有没有落地」这一维的参照。

#### 4.6.2 新方案：执行环节汇报「结果块」，报告按块渲染

**有约束的自由，两层分开定**（与 §4.5.2 的两层分离同一思路）：

| 层 | 谁定 | 定什么 |
|---|---|---|
| **语义层**（PRD 定，落在提示词） | 产品 | ①每块要有给人看的**中文标题**；②🔴 **每个数字都要说清出处，且出处只有两种**——**本次跑出来的**（哪个产物文件、哪一步）／**论文报告的**（来自论文分析送进来的报告值）；**两种出处不得混同、不得让读者分不清哪个数是谁的**；③**若上下文给了论文报告值**，论文值与本次复现值**必须在同一块内可对照**；④**不得覆盖或合并**不同来源的同名数字 |

**渲染原语（代码提供通用容器，不是业务格子）**：块 = 标题 + 可选说明 + 可选表（**列名与列数由 agent 给**）+ 可选来源引用。报告**按 agent 给出的顺序渲染，代码不排序**——今天 `reporting.py:997` 的 `sorted()` 是代码在替 agent 决定组的先后。

#### 4.6.3 🔴 必须正面回答：不预设结构，报告怎么渲染

**答：汇报自带展示所需的元信息（self-describing），而不是让渲染层去猜。**

当初那次否决的**合理内核**是"下游拿到任意嵌套 JSON 不知道怎么展示"——**这个担心成立，回炉不能把它一起扔掉**。但解法不是把数据压回二维，而是**让上游把"怎么展示"一起说了**：执行环节是唯一知道"这些数字是什么、该怎么并排看"的角色（目录是它建的、命令是它发的、产物是它读的），让它顺带给出标题与列名**边际成本几乎为零**；让代码去猜则要写一堆启发式，而启发式猜错是静默的。

**技术可行性已由架构核实**：
- finalize 的**主通道本来就是 `<result>` 标签里的自由 JSON**（`core/react_base.py:713-716`），**任意形状今天就能流过来**；`EXECUTION_OUTPUT_SCHEMA` 只在"预算耗尽"与"解析失败重生成"两条**兜底路径**生效。
- 实测为**非 strict**（`react_base.py:431` 调 `with_structured_output` 未传 `strict`）；旁证：`execution.py:1138` 的 `"additionalProperties": True` 在 OpenAI strict 子集里非法，而它今天跑得通。
- **列名做成数据、不做成 schema 键**：`columns: [str]` + `rows: [[str]]` 位置化表示 ⇒ 任意列数可表达，且**在 strict 子集内也合法**（将来要开 strict 不必重做）。

🔴 **单元格一律字符串**，三条理由：①union type 不在 strict 子集内；②渲染终点本就是 Markdown 表；③**一旦 cell 是数值，下个 Sprint 必然有人写"取 cell 数值做比较"——那就是本次病根的原样复发。** 代价：失去"值是数值"的类型保证（该保证本 Sprint 已无消费者——`_decide_conclusion` 只读档位 + 数封顶）。

🔴 **结果块字段不得进 `required`**：`react_base._missing_required_fields`（`:486-497`）把**空数组也算缺失** ⇒ 跑挂了的零结果回合会每次白烧一次 schema 重生成调用。与 `metrics` 刻意不进 required 逐字同源（`execution.py:1090-1091`、架构 AR-S8-07）。

#### 4.6.4 与物证的关系：**一份台账 + id 引用**（不是内联）

PM 原判断是"物证与展示应当是同一份数据、不是两套"，**方向对、结构上差一层**（经架构评估订正）：

- **粒度不同**：物证的粒度是**每条判断**，结果块的粒度是**一张表**（一张表可能有 12 行、来自 2 个文件）。
- **内联的两个后果**：①同一个结果文件在 N 个块里重复出现 ⇒ 验钞读盘跑 N 次；②逐条结论里的证据与块里的证据成为**两处独立数组** ⇒ **这恰恰就是本节要防的"漂移成两套"，内联等于把漂移写进结构。**

⇒ **唯一证据台账 + id 引用**：证据台账是唯一的（路径、读到的值、来自哪一步、验钞结果**只此一处**，**验钞只跑一次**）；**逐条结论与结果块都只持 id 引用**。⇒ **结构上不可能漂移成两套**。渲染时，引用到"未过验"证据的块**显著标注**——这才是 S8-04 与 S8-06 的真正接口。

⚠ **代价说实话**：id 由 agent 自己生成、**可能悬空**。处置（纯确定性、零模型）：台账里查不到的 id → 丢弃该引用 + WARNING + 该块标注"来源引用无效"，**绝不因此丢弃整块**。

⚠ **本条修订了 `docs/sprint8/architecture.md:156` 已定稿的内联证据形态** ⇒ 见 §13 待拍板第 5 条。

#### 4.11.2 护栏 1：成功标准在计划审核页显眼可见可改

#### 4.11.3 护栏 3：成功标准必须引用论文的具体主张（**PM 定：提示词 + 确定性告警，双落点**）

**产品决定：两者都做，但确定性检查只做最弱的一档——只挡空话、只产警示、不阻断审批。**

**四条理由**：

1. **只写提示词的证据强度等于零**——只能证明"提示词里写了这句话"；本项目实测提示词服从率约 **75%**，S7-06/S7-07 已两次栽在"模拟层全绿、真实行为没达成"。
2. **这条护栏防的是产品定义级假成功**（标准画低 ⇒ 任何论文都判成功），后果量级等同 S7-10 约束 C（"违反了会静默产出错误结论"），而约束 C 的裁决正是**必须落在工具层、不接受只写提示词**。
3. **但不能做成硬门**：「什么算引用了论文的具体主张」**没有确定性判据**，硬拦必然误伤——同 S7-10 约束 A/B 只能软保证的逻辑。
4. **零新机制**：`core/plan_checks.py:483` `check_plan` 已有 W1~W5 五条确定性告警，**只产警示、不阻断审批**，唯一消费点 `ui/pages/plan_review.py:786` 是现成的警示卡片 ⇒ **加第 6 条是零新机制、零新展示通道、函数签名不变**。

**判据（纯字符串、零 IO、可单测、低误伤）**：成功标准文本中**是否出现至少一个来自论文分析的事实层名词**（`paper_analysis.metrics` / `datasets` 的英文名，或论文报告值里的键名）。命中不到即报「成功标准未引用论文的任何具体指标或结论」。

## 11. 产品结论小结

- **目标用户**：CS 领域研究者与学生，**特别是三类此前被结构性挡在门外的人**——复现定性论文的、复现无对照组论文的、以及"数跑出来跟论文对上了"却评不上最高档的。
