## 6. 新发现：指标链路两条独立失效线（★ 本次最重要的产出）

> **定性**：均**非本批引入、非本批回归**。是 S7-11 把「少跑步骤却判成功」堵上之后，才浮出的下一层。

### 6.1 线一：主指标被吞（`<METRICS>` 通道）

**现象**：`report.md` 的「本次复现值」印的是 `mean_timing_seconds = 44.81` 与 `num_result_records = 12`——**运行时元数据，不是科学指标**。而真实的 k-NN 准确率**同在一份日志里**。

**机制**：

- `execution.py:530` `stdout = "\n".join(...)` —— 把 **12 个步骤的 stdout 串接成一份**，步骤归属在此丢失；
- `execution.py:403` `_extract_metrics_block` —— docstring 明写「取**最后一个** `<METRICS>` 块（容忍中途打印）」，`for raw in reversed(matches)` 命中即返回。

**实测 round_2 共 9 个 `<METRICS>` 块**（agent 每步打一个，格式全部合法）：

| # | 来源步骤 | 内容 |
|---|---|---|
| 1 | check_umap_import | `{"umap_import": 1}` |
| 2 | prepare_datasets | `{"failed_count": 1, "prepared_count": 3}` |
| 3 | run_umap_benchmarks | `{"mean_timing_seconds": 44.814, "num_runs": 12, "skipped_datasets": 1}` |
| 4-6 | run_baselines ×3 | `{"mean_timing_seconds": …, "num_runs": 3, "skipped_datasets": 1}` |
| **7** | **evaluate_knn_accuracy** | **`{"best_knn_accuracy": 0.987, "mean_knn_accuracy": 0.8006, "num_evaluated_runs": 21}`** ← **真指标，被跳过** |
| 8 | plot_embeddings | `{"num_plots": 21}` |
| **9** | **summarize_results** | `{"datasets": […], "mean_timing_seconds": 44.814, "methods": […], "num_result_records": 12}` ← **被采纳** |

**根因**：「取最后一个」的原意是**容忍同一个脚本边算边打印草稿值**（单脚本时代成立）。进入 12 步流水线后，「最后一个」的语义**静默漂移**为「最后一个**步骤**」——而规范的计划总把汇总步骤放在最后，**汇总脚本天然输出元数据而非科学指标**。**计划写得越规范，越会踩中。**

**三条连带后果**：

1. **成功条件被元数据满足**：「至少解析出 1 个指标」这一合取项，实际是被 `num_result_records = 12` 满足的；
2. **`skipped_datasets = 1` 一并丢失** —— agent **诚实报告了**"跳过 1 个数据集"，是系统把它丢了（见 §6.3）；
3. 报告指标对比表对读者产生误导性完整感。

**已实测的合并效果**（零改动模拟，仅供修法参考）：合并全部 9 块 → **11 个指标**，`best_knn_accuracy` / `mean_knn_accuracy` / `skipped_datasets` 全部回归。⚠ 但**朴素合并会引入新问题**：`mean_timing_seconds` 被 4 个步骤争用、`num_runs` 被 2 个争用，后者覆盖前者后 **`num_runs` 会印 3（基线的），而主实验实际跑了 12 组** —— 张冠李戴比丢失更隐蔽。**⇒ Maria 已拍板：不得覆盖，须按步骤区分并全部展示。**

### 6.2 线二：产物文件通道整塌 → 计划预期回验瘫痪（**比线一严重**）

**现象**：`report.md`「计划目标回验」**5 条预期全部 ⚠️ 未验证**；「分组实验指标」4 组全部「该组未解析出指标字段」。

**机制**：

- `execution.py:1592 _collect_grouped_metrics` 扫 `outputs/**/summary.json`，规则是**只收顶层数值/布尔/短字符串字段**（`:1625-1630` 顶层非 dict 直接 `continue`）；
- 本次 agent 实际写出的结构：

| 文件 | 顶层形态 | 结果 |
|---|---|---|
| `outputs/eval/summary.json` | **数组**（21 条记录，**含 `knn_accuracy`**） | 整份跳过 |
| `outputs/umap/summary.json` | dict，但字段是 `completed_runs` / `skipped_datasets`（**均为数组**） | 全字段跳过 → 组空 |
| `outputs/baselines/{pca,laplacian_eigenmaps,tsne}/summary.json` | 同上 | 同上 |

- ⇒ `metrics_groups = {}` ⇒ `reporting.py:188` `_verify_trend` 首句 `if not (… and metrics_groups): return 未验证` ⇒ **所有 trend 条目直接判"未验证"，回验从未真正执行**。

**根因（★ 已修正，见 §5.2）**：**不是 agent 不服从，是契约缺失。** `coding.py` 对 `summary.json` 的结构**零字要求**；系统单方面假设了"顶层放标量"。

**★ 本次最有力的实证对照**：

> **同一个 agent、同一次运行** —— 说清楚的约定（`<METRICS>`，给了格式 + 例子 + 边界）**9/9 全对**；没说的约定（`summary.json`）**无从服从**。

### 6.3 关联：问题一「步骤跑满但内容被掏空」

计划要求 4 个数据集，**coil20 在公开数据源不存在**（`round_2.log:79` 原文 `Failed dataset: coil20 error: Dataset coil20 with version 1 not found.`）。agent 第 2 轮修法为「检测数据集目录是否完整，缺失则跳过并写入 skipped 记录」（`fix_loop_history[1].fix_note` 原文），命令因此 **exit 0**。

**结果：步骤对账 12/12 满分，实际实验内容少做 1/4，判定层不可见。**

⚠ **但归因须精确**：agent **在 `<METRICS>` 块里诚实写了 `skipped_datasets: 1`**（块 3~6，共 4 次），**是线一把它丢了**。⇒ 「判定层看不见跳过」**至少一半是系统的信息丢失，而非 agent 隐瞒**。

**定性**：完整度是否应管到"实验内容"而不止"步骤条数"，属**产品语义扩展 → 走 PRD**。
