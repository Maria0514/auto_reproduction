### 3.3 三条负向状态断言（AC-S7-25，须"一字不动"）

| 断言 | 实测 | 判定 |
|---|---|---|
| 未走 force_finish | 4 个 ReAct 子图（intake/analysis/scout/planning）**均正常 finalize**（checkpoint `branch:to:finalize` 恰 4 次）；轮次上限 30，实际工具调用轮次远低于上限 | ✅ **成立** |
| 未进 `degraded_nodes` | ⚠️ **实测为 `['paper_intake', 'resource_scout']`** | ⚠️ **形式上不成立，但归因与探测无关**，见下 |
| `resource_strategy` 未被改写为从零实现 | ⚠️ **实测为 `from_scratch`** | ⚠️ **同上** |

**归因（已逐条上磁盘查证，不是推测）**：

1. `paper_intake` 降级原因 = `"LLM 漏写中文字段 *_zh，已回退原文主字段值"` —— **既有的 LLM 服从度问题，与 S7-08 无关**。
2. `resource_scout` 降级原因 = `"未找到可用的开源代码仓库，已降级为从零实现"` —— 这是**业务结论而非探测故障**：
   - `paper_meta.github_url` = **null**（论文本身未提供仓库链接）
   - `resource_info.repos` = **[]**、`selected_repo` = **null**（web search 兜底亦无果）
   - ⇒ 走 prompt 既定的搜索优先级链第 3 步「全部失败 → `from_scratch`」，是**设计内的正确行为**
3. **排除「探测挤占搜索预算」这一反向风险**：`REACT_MAX_ROUNDS_RESOURCE_SCOUT = 30`，本次探测仅 7 条命令，且 prompt 要求「尽量集中在一轮里一次性给出」；子图正常 finalize 未 force_finish ⇒ 搜索未被探测挤掉。
4. **旁证**：该论文在 S7 早期复现记录中亦为自写代码路径（TODO 登记的 `train_k_predictor.py` 缺 `sys.path.insert` 缺陷即出自该篇的 from_scratch 产物），**说明无公开仓库是这篇论文的固有属性，非本批引入的退化**。

> **处置结论**：这两条负向断言的**原始设计意图**是「新增探测不得把节点搞崩、不得挤占搜索」，
> 该意图**实测成立**。断言的字面形态在「论文本身无仓库」的靶上不可满足，属**靶选择与断言口径
> 的错配**，非缺陷。**本报告不修改该断言**（AC-S7-25 三条负向断言按纪律"一字不动"），
> 改为在此显式登记口径说明；若未来要让该断言可判，需换一篇**有公开仓库**的靶。
