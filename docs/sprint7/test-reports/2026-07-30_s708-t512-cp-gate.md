## 3. 两处口径订正（本任务上磁盘核实，**推翻 dev-plan 既有记载**）

### 订正 1 —— CP-5.12-7 的 payload 守门是"既有 + 已同步"，不是"新造"

- **dev-plan 原记载**：§32.4 前置事实 5 与 §40 **P-16** 均称"全仓**不存在**『planning interrupt payload 键集合恰为 N』的断言"，并据此登记 **R-S7-46**、把 CP-5.12-7 定为"**新造**两道守门"。
- **实际情况**：`tests/test_sprint4_e2e.py::test_cp_g2_1_three_interrupts_serial_same_thread` 里**一直存在**一条精确的 planning interrupt payload 键集合断言：

  ```python
  p1 = obs["pause1_ivs"][0]          # planning 第一次中断的 payload
  assert set(p1.keys()) == { ...10 键... }, f"interrupt#1 payload 键集不符: {sorted(p1.keys())}"
  ```

  它断的确实是 **planning** 的 payload（同段紧接着就读 `p1["revise_count"]` 与 `p1["reproduction_plan"]`）。P-16 把它误认成了同文件 `:632` 那条 **user_input** interrupt 的 4 键断言。
- **本批的实际动作**：S7-08 加 `local_env_facts` 后该断言按设计打红，**已由主控同步为 11 键并保持精确相等（未弱化为 issubset / `>=`）**，diff 只有 +1 键 +3 行注释。
- **本任务的处置**：**只做收口复核，未新造重复断言**。落地为
  `test_cp_5_12_7_payload_key_set_guard_is_present_precise_and_complete`——复核该守门①仍在、
  ②形态仍是 `set(p1.keys()) == {...}` 精确相等（显式排除 `>=` / `<=` / `issubset` / `issuperset` 四种弱化写法）、
  ③键集合恰为既有 10 键 + `local_env_facts`。
  另补 `test_cp_5_12_7_payload_guard_runs_in_default_regression`——AST 断言该文件**无模块级 `pytestmark`**，
  防这道守门哪天被整体 deselect 出默认回归（文件名带 `_e2e` 但只有类级 `pytestmark`，风险真实存在）。
- **结论**：**R-S7-46 的前半（payload 侧）不成立**，建议主控据此订正 §32.4 事实 5 与 §40 P-16。
  R-S7-46 所描述的失效模式本身仍成立，只是形态从"守门缺席"变成"守门可能被悄悄弱化"——
  两者后果完全一样，故复核断言仍有必要。

### 订正 2 —— "决策恰 5 类"在源码层面是 **4 + 1**

- **源码事实**：`ui/pages/plan_review.py` 里走 `controller.resume_with(thread_id, {"decision": ...})` 的字面量**只有 4 个**——`approve` / `code_only` / `revise` / `switch_repo`；第 5 类"取消"走 `controller.cancel_task(thread_id)`，**不经决策通道、没有 decision 字面量**。

  `_EXPECTED_DECISION_COUNT = 5` + `assert found == _EXPECTED_RESUME_DECISIONS` +
  `assert "controller.cancel_task(thread_id)" in src` + `assert len(found) + 1 == _EXPECTED_DECISION_COUNT`。
- **本任务的处置**：**未改既有断言、未为凑"恰 5 个字面量"把断言写松、也未生造第 5 个字面量**。
  落地 `test_cp_5_12_7_decision_set_guard_is_present_and_precise` 复核这五条断言逐条仍在且未被弱化。

### 10.1 P-9（`test_plan_review_e2e.py::test_e2e_code_only`）——实测行为与 dev-plan 记载**不完全一致**

  由于**执行顺序确定**（本仓库未装 `pytest-randomly`，已核实 `pip list` 无该插件），全量回归里它**确定性通过**。
